What BREADCRUMBS is

An always-on, on-prem food-safety agent for a NYC food operator. When an FDA recall drops, it tells the operator — in seconds, offline, on the GB10 — which of their locations are exposed, how bad, and what to do. Not a dashboard: an agent that watches, reasons, and acts.

"When a food recall drops, BREADCRUMBS tells a NYC operator which of their sites are exposed and what to do — on a box in the back office, data never leaving the building."

Why it wins this hackathon

Dell/NVIDIA are judging local AI on their hardware. Our edge: a buyer's supplier list is a trade secret they'd never send to a cloud LLM → the agent must run on-prem → the GB10 is the product, not a demo prop. FSMA 204 makes food traceability a legal mandate on top.

The wow we build toward

The map is the stage; the AI agents + the GB10 are the star. Four pieces, all frontend-heavy:

  1. Agent swarm view — Watcher → Tracer → Risk → Briefer → Comms, running concurrently, each a live card with status + streaming output. The "five agents in parallel on one box" flex.
  2. GB10 telemetry panel — tokens/sec, GPU memory, watts, model name, as console chrome. Cheapest proof it's really on the hardware.
  3. Live agent reasoning — Nemotron's actual streamed tokens over the real recall text (replacing today's placeholder narration).
  4. SMS / Comms action — the Comms agent drafts + fires an SMS to affected site managers. A real phone buzzing on stage is the most tangible wow in the room. Pillar 3.

Where we are — built + real

Real data — all free, offline-cacheable (globe/assets/)

  • nyc-restaurants.json — 17,204 geocoded NYC restaurants w/ DOHMH health grades.
  • nyc-stores.json — 11,224 food stores · nyc-nta.geojson — 262 neighborhoods.
  • distributor-scorecard.json — real openFDA recall history (Dole 205 Class-I, Sysco 24, Baldor 0).
  • food-types.json / food-sources.json — recall risk by category + import origins.
  • manhattan_buildings.json — 45,194 buildings w/ LiDAR heights (Sixth Borough engine).

Consoles (globe/)

  • food3d.html — primary. Pitched 3D NYC, extruded buildings, risk hexbins, distributor hubs, recall-trace.
  • food.html — 2D fallback · maritime version lives on main.

Where you plug in — pick a lane

Scope firmed up in person. Three lanes; grab whichever fits.

Frontend / UI

  • Polish food3d.html — layout, motion, the C2 aesthetic (docs/design-system.md: amber/cyan on near-black, hairline borders, Plex / JetBrains mono).
  • Agent-swarm panel + GB10 telemetry HUD — the wow. Static mock first, wire later.
  • SMS / Comms action UI — the draft + send flow, phone-mockup for the demo.
  • Product / pitch one-pager — mockups/product-concept.html is a start.

Agent / backend

  • The swarm (Watcher→Tracer→Risk→Briefer→Comms) via NemoClaw (primary; OpenClaw for off-box dev) — tool-calls over MongoDB, local Nemotron on the GB10.
  • The recall-response engine — exposure × risk × action (see PRD.JSON M2).

Data / infra

  • MongoDB — load + index the cached datasets, geospatial + aggregation queries, change-stream watcher (see PRD.JSON M0).
  • Offline vendoring — deck.gl + fonts local for the unplugged demo.

Stack — deliberately dependency-light

deck.gl 9 standalone from unpkg (one <script>), vanilla JS, no framework, no build. Each console is one self-contained .html. Data is static JSON over a local server; Python only for the fetchers.

Offline note: for the GB10 demo, deck.gl + fonts must be vendored locally (still on unpkg now).

Run it

git clone https://github.com/TheApexWu/breadcrumbs.git && cd breadcrumbs
git checkout food
cd globe && python3 -m http.server 8777
# open http://localhost:8777/food3d.html

Click a distributor in the scorecard → camera traces its establishments. Then hit ⚠ SIMULATE RECALL.
